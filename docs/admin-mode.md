# 管理者モード

マップ上部の「管理者モード」は、サーバーが管理者と判定したアカウントだけに表示します。表示名、手動Slack ID、ブラウザー内の値、WebSocketの追加フィールドを変えても権限は得られません。権限判定は画面の表示とは別に、サーバー側で保存のたびに実施します。

## tt-asaharaの本人確認

管理者本人は `tt-asahara@kddi.com` として確認済み。

- Slackログイン：署名検証済みIDトークンのメールが一致し、`email_verified=true` の場合だけ初期管理者として利用できます。最初の設定保存時に `slack:<team_id>:<user_id>` を設定ファイルへ固定し、以後はその不変IDだけで判定します。同じメールを持つ別ワークスペース・別ログイン方式へ自動では権限移譲しません。
- Microsoftログイン：メールや `preferred_username` では管理権限を付与しません。Azure構築を再開したとき、会社テナントで本人のObject IDを確認し、`WAIWAI_ADMIN_ACCOUNT_ID=entra:<tenant UUID>:<tt-asahara object UUID>` をサーバー環境へ設定してください。メールが変わっても同じIDを維持します。明示IDがある場合は、Slackの初期管理者判定より優先します。
- Slackの既存セッションにはメールがありません。SlackアプリのUser Token Scopesに `email` を追加し、Waiwaiからログアウトして再ログインしてください。未確認メール・ゲストには管理者画面を表示しません。

参考：[Slackのメールスコープ](https://docs.slack.dev/reference/scopes/email/)、[MicrosoftのIDトークンと不変ID](https://learn.microsoft.com/en-us/entra/identity-platform/id-token-claims-reference)。

## 管理画面

「サーバーと所属を管理」からチームごとのオフィスを追加し、メンバーの入室先を設定できます。フロア等の表示許可は、現在入室しているサーバーにだけ適用します。詳細は[サーバーと所属管理](servers.md)を参照してください。

4つのカテゴリを切り替え、名前や番号で検索し、チェックを付け外しすると即座に保存します。チェックありは許可、なしは禁止です。事件・うろちょろ・ポケモンはカテゴリ全体を休止でき、再開時は個別設定を保持します。ポケモンは登録済み全種、事件は365件を選べます。

- フロア：閉鎖中は一般ユーザーの部屋一覧・右側ショートカットから非表示にし、公開中の部屋数も更新します。管理画面には残るので再公開できます。通常移動、ワープ、ルーラ、コール、開発用の出現指定でも入れません。すでにいる人は公開中の先頭フロアへ退室し、元の部屋との音声接続と対戦・ゲーム参加を終了します。入室口も公開中の部屋から選びます。全フロアの同時閉鎖は拒否します。家具や登録URLは消しません。
- うろちょろ：犬・猫・ロボット掃除機の常駐キャラを個別に設定。閉鎖中の部屋の住人も表示しません。個人の犬・猫バディの設定は対象外です。
- 事件：禁止した事件と閉鎖部屋の事件は出さず、許可された別の事件を、その事件に設定された部屋で表示します。表示できる事件がなければお休みになり、マップ・窓の演出・館内カレンダーに表示しません。個人の発見記録を削除しません。
- ポケモン：日次の抽選候補・開発用出現・バディから除外します。日次は許可種から最大7体、開いている部屋だけに配置します。すでに同行中の禁止種も表示を終了します。個人の選択や図鑑記録自体は保持し、再許可すると選択済みバディも戻ります。

## 保存と運用

ポケモンのタブでは、赤・緑／金・銀からスカーレット・バイオレットまでの9世代と、発表済み・図鑑番号未公表の種類をチェックボックスでまとめてON/OFFできます。全国図鑑の初登場世代で分類し、第7世代にはメルタン・メルメタル、第8世代にはヒスイ地方の追加分を含めます。世代の範囲は固定して取得したPokéAPIの`pokemon_species.csv`の`generation_id`と一致します。

世代の設定は`blocked.pokemon`の`generation:1`〜`generation:9`と`generation:announced`に保存し、個別の種類の禁止とは独立して保持します。世代OFF→ONでも個別の禁止を解除せず、図鑑の記録も削除しません。ポケモン全体をOFFにした場合も世代のチェック状態は保持します。世代の禁止は通常の出現抽選・開発用の強制出現・バディ表示に同じルールで適用し、再起動後も継続します。

保存先は `WAIWAI_POLICY_FILE`、未指定時は `WAIWAI_DATA_FILE` と同じディレクトリの `office-policy.json` です。Azureでは既存データディスクの `/var/lib/waiwai/office-policy.json` になり、既存バックアップ対象に含まれます。認証情報・実際の管理者ID・設定ファイルをGitへ登録しません。複数タブの変更はリビジョンで競合を検知し、古い画面からの上書きを拒否します。保存に成功するまで全員への設定変更は適用せず、保存失敗時は前の設定を維持します。破損ファイルは設定なしとして起動せず、バックアップからの復元を要求します。

管理権限の移行はサーバー環境の明示IDを本人の不変IDへ変更して再起動します。管理画面から別のユーザーへ権限を付与する機能は設けていません。今回の変更ではAzureのapplyやデプロイは実行しません。
