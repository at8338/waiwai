# 上下左右につながる一枚マップ

上部の格子アイコン「一枚マップ／従来の部屋表示」で切り替える。通常表示では「上下左右につながるマップ」ボタンを使う。初期表示は従来の部屋方式のまま。

一枚マップでは、既存の16エリアを4列×4行に固定配置する。各エリアは従来と同じ30×20マス、表示窓も同じ大きさ。全体は120×80マスとなり、アバターの移動にカメラが追従する。隣接エリアは境界を越える前から同時に表示され、画面切り替え・フェード・部屋選択は発生しない。矢印キー、WASD、ダッシュ、クリック移動は同じ世界座標で動作する。

| | 左から右への並び |
| --- | --- |
| 1行目 | ひだまりオフィス・集中室・作戦室・カフェ |
| 2行目 | 図書室・ガーデン・アトリエ・ゲームセンター |
| 3行目 | 休憩室・工房・ラウンジ・管制室 |
| 4行目 | 操縦室・案件部屋・食堂・闘技場 |

共有する壁は、両側の固定家具と内部の壁を避けて通路になる。外周と角には通路を作らない。管理者がエリアを禁止しても配置は詰め直さず、隣接通路を閉鎖する。動的な家具と氷の盾、速度制限、寝転び中の移動禁止はサーバーで引き続き検証する。

表示方式は接続ごとに選択でき、従来表示のユーザーとも同じアバター・配置データを共有する。サーバーではエリアIDとエリア内の座標を保持し、境界の一歩を世界座標に変換して処理する。境界通過は `move` / `dash` のままで、メニューからの `change-room` を送って移動する方式ではない。エリアIDが変わる際は、圧縮位置フレームに先行して完全なプレイヤー状態を配信する。

チャット、近接音声、ゲーム・魔法などの所属エリアと権限判定は既存仕様を維持する。家具・小物、ペット・バディ、落とし物、事件、照明は隣接エリアも描画する。画面外のエリアはまとめて描画を省略する。従来表示へ戻す際、通路だった壁の上にいる場合は同じエリアの安全な床に戻す。Azureの構成・デプロイは変更しない。

検証は `src/game/continuous-world.test.ts` と `server/office.test.ts` の continuous テストで行う。全エリアの到達性、四方向の隣接関係、禁止エリア、クリック経路、境界補間、標準表示との同期、通常の壁の復帰を確認する。

150接続で一枚マップを検証する場合は `LOAD_CONTINUOUS=true LOAD_BUDDIES=true LOAD_SECONDS=20 npm run test:load` を実行する。全16エリアに分散して移動し、境界を実際に通過したこと、全員の接続維持、応答時間、30人の音声シグナリングを確認する。音声メディアの帯域とブラウザの描画性能はこのサーバー負荷試験の対象外。

2026-10-18のmacOS/arm64での20秒試験では、150人・150バディ・30人の音声シグナリングで18,840回の移動要求、469回の境界通過、予期しない切断0、移動応答p95 10.0ms、イベントループp99 19.0msを記録した。サーバーCPUは1コア換算18.9%、RSS 161.4MiB、全クライアント向けの合計送信量は42.1Mbps。全員が約160msごとに移動し続ける試験条件であり、Azure上の性能や通常利用時の通信量を保証する値ではない。

境界通過ではプレイヤー配信からメンバー検索の現在地を更新し、全員分の一覧を再配信しない。同一アカウントの複数タブがある場合は、検索結果の移動先として選ばれているタブだけがその行の現在地を更新する。入退室・プロフィール変更時の一覧配信は従来どおり。
