# 近接音声

ブラウザー標準のWebRTCとWeb Audioを使った、少人数向けの近接音声です。音声はブラウザー間で送受信し、既存のWebSocketサーバーが参加・接続情報の交換を管理します。LiveKitは未導入です。

## 使い方と聞こえる範囲

- 最初は音声未参加・マイクOFFです。「音声に参加」は受信を有効にする操作で、マイク権限を要求しません。
- 「マイクをON」で音声のみを取得します。カメラの取得、録音、文字起こしはしません。
- 同じ音声ゾーンで、アバター間のユークリッド距離が5マス未満の場合に接続します。1.5マス以内で通常音量、それ以遠で線形に減衰します。
- 上側の3部屋はそれぞれ独立したゾーンです。入口と下側のフリースペースは共通ゾーンです。部屋の境界を越えると距離にかかわらず切断します。
- 距離やゾーンが変わったら音量を更新し、範囲外では接続を閉じます。再接近すると新しいセッションで接続します。
- 「マイクをOFF」では取得したトラックを停止し、送信側のトラックも外します。受信は続けられます。
- 「音声を終了」やオフィスの切断・画面破棄では、入力トラック、音声接続、再生ノードを解放します。マイク取得の許可待ち中に終了した場合も、後から届いたトラックを停止します。
- 話している人には参加者一覧とアバター名に音符を表示します。判定は受信側での音量による簡易検出です。
- オフィスが再接続されても音声やマイクは自動復帰しません。ユーザーが参加し直します。

## 接続の制御

サーバーは音声参加中の人だけを対象に、確定したアバター位置とゾーンから接続可能なペアを計算します。ペアごとにセッションIDを発行し、その相手・そのセッションへの音声接続情報だけを中継します。範囲外になったり退出したりするとペアを破棄し、古い接続情報は中継しません。動画・データチャネル向けの接続情報も拒否します。

音量をゼロにするだけで全員に送り続ける構成にはしていません。ただし音声はP2Pなので、サーバーがメディア配信そのものを強制制御するSFUとは異なります。厳密な私的会議室や配信権限が必要になる段階では、LiveKitなどによるサーバー側の配信制御を検討します。

同時に音声へ参加できるのは30人までです。アバター全体は150接続までです。各端末の音声接続は最大4人で、5人以内の小グループを想定しています。密集時には案内を表示します。30人が一斉に相互通話する用途には対応しません。試験の条件は[Azure公開手順](azure.md)を参照してください。

## HTTPSとネットワーク

マイク取得にはセキュアコンテキストが必要です。同じPCの `http://localhost` / `http://127.0.0.1` では試せますが、LAN内IPへのHTTP接続では音声を開始できません。[getUserMediaの仕様](https://developer.mozilla.org/en-US/docs/Web/API/MediaDevices/getUserMedia#privacy_and_security)

別端末から使う場合は、信頼された証明書を持つHTTPSリバースプロキシでアプリを配信し、同じホストの `/office` をWebSocketとして転送してください。Hostヘッダーを維持します。HTTPSページからは自動的に `wss:` を使います。自己署名証明書の警告を回避する設定は追加していません。

既定では外部のSTUN / TURNサービスへ接続しません。ローカルや直接接続できるネットワークではホスト候補を使います。異なるネットワークやNAT・ファイアウォール越しでは、環境に応じたSTUN / TURNを設定してください。[ICEサーバー設定](https://developer.mozilla.org/en-US/docs/Web/API/RTCPeerConnection/RTCPeerConnection#iceservers)

サーバー環境変数 `RTC_ICE_SERVERS` にICEサーバーのJSON配列を設定できます。たとえば次は架空のTURNサーバーの設定例です。

```bash
RTC_ICE_SERVERS='[{"urls":"turns:turn.example.com:5349","username":"TEMP_USER","credential":"TEMP_PASSWORD"}]' npm run dev
```

本番用ビルドでも同じ変数を `npm start` 時に設定します。ICE設定はブラウザーの接続に必要なので、音声に参加したクライアントへ渡します。運用では短期間有効なTURN資格情報を使用してください。実際の資格情報をリポジトリにコミットしないでください。`TURN_SHARED_SECRET`（32文字以上）と `TURN_URLS`（カンマ区切り）を設定すると、30–60分有効のTURN資格情報をサーバーが自動発行・更新します。共有鍵はブラウザーへ渡しません。Azure構成ではSlack認証を必須にしています。

## 検証

`npm test` は距離による減衰、部屋の境界、参加への同意、近接ペアの発行・失効、古いセッションの拒否、音声参加の上限を検証します。

実際のWebRTC送受信は、開発サーバーの `/tests/voice.html` を2つのタブで開いて検証できます。2つとも「音声に参加」を押し、一方で「テスト音のON / OFF」を押します。実マイクの代わりに低音量の440Hz合成音を使います。

このページはテスト用で、本番用ビルドには含まれません。

- `受信あり` と受信RMSから、接続しただけでなく音声が届いたことを確認できます。
- 「少し離れる」で減衰、「遠くへ」で接続が閉じて無音、「入口に戻る」で再接続を確認できます。
- テスト音のOFFや音声終了で `track-state` が `ended` になることを確認できます。
- 「権限拒否を模擬」で許可されない場合の表示と、聞くだけの参加が続くことを確認できます。
- 「取得待ちを模擬」→「音声を終了」→「取得を完了」で、遅れて取得したトラックも停止することを確認できます。

開発時は上記の合成音による双方向送受信、近・中・遠距離、再接近、ミュート、終了、権限拒否の模擬、取得待ちのキャンセルを確認しています。実マイクを使った2台の物理端末、Safari / iOS、別ネットワークやTURN経由の実通信は未検証です。
