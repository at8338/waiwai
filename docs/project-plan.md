# Waiwai 開発計画

作成日：2026-10-17（日本時間）

この文書は[共有会話](https://chatgpt.com/share/6ad317da-0558-83ee-8118-d0a30c321a2b)と、その後の命名・リポジトリ指定を引き継ぐためのものです。ユーザーの希望と、アシスタントの提案を分けて記録します。

## ユーザーが示した希望

- Gatherのような、リモートワーク中に集まれるWebアプリを自作したい。
- すべてを作り直す必要はなく、既存OSSを活用して主要な要素を作りたい。
- テキストチャットはSlackを使いたい。
- ミーティングも可能ならSlackを使いたい。難しければチャット連携だけでもよい。
- 「近づいたらワイワイ声が聞こえる」体験の魅力に関心がある。
- サービス名はWaiwai、開発先は `at8338/waiwai`。

## 提案中の方向性

2D空間で人の存在を感じ、近づくことで偶発的な会話に参加できる体験を検証します。テキストでのやり取りにはSlackを使います。

近接音声の採用はまだ明示的に確定していません。前の会話で提案された構成を出発点として、最小の実装で有用性を確かめる方針です。

## 技術候補

以下は前の会話で挙がった候補です。採用やバージョンは未決定で、実装時に公式資料と互換性を確認します。

| 領域 | 候補 | 役割 |
| --- | --- | --- |
| UI | React / Next.js、TypeScript | 入室画面、参加者一覧、音声操作 |
| 2D空間 | Phaser | マップ描画、アバター操作、衝突判定 |

WorkAdventureを基盤にする案もありましたが、採用は決まっていません。選ぶ場合は機能だけでなく、その時点のライセンスと利用条件も確認します。

## 最初のMVP案

### 1. オフィスを歩く

- 小さなマップをブラウザーに表示する。
- 名前付きのアバターをキーボードで移動できる。
- 壁や家具など、通過できない場所を設ける。

確認方法：ブラウザーで移動し、障害物やマップの境界を通過しないことを確かめる。

### 2. 同じ場所に集まる

- 2つのブラウザーから同じ空間へ入室できる。
- 他の参加者の移動が同期される。
- 退出・切断した参加者が適切に消え、再接続できる。

確認方法：2つの独立したブラウザーセッションで移動・退出・再接続を行う。

### 3. 近づいて話す

- 参加者が近づくと音声が聞こえ、離れると聞こえなくなる。
- 初期状態はマイクOFFとし、ユーザーの操作で有効にする。
- ミュート、音声の接続状態、誰と会話できるかを表示する。
- マイクを許可しなくても、オフィス内を移動できる。
- 同意なく録音・文字起こしを行わない。

確認方法：ヘッドセットを使った2台の端末で、距離による聞こえ方、相互のミュート、権限拒否時の動作を確認する。

### 4. Slackへつなぐ

- 相手のアバターからSlack DMを開く導線を設ける。
- 必要に応じて、場所に紐づくSlackチャンネルへの導線を設ける。
- 最初は手動のSlack ID設定も候補とし、認証方式の決定を待たずに導線を検証する。
- Huddleの開始・参加の自動化は、公式の対応範囲を確認してから決める。

確認方法：設定されたワークスペースと相手のDMが開くことを確認する。メッセージの自動送信はMVPに含めない。

## 後続の検討事項

- 想定人数、チーム内利用か外部向け提供か。
- Slackアプリを開く方式でよいか、アプリ内チャットが必要か。
- Slackログイン、ゲスト参加、利用可能なワークスペースの制限。
- 会議室、デスク、集中状態と、音声が届く範囲の関係。
- ビデオ通話・画面共有の必要性。
- ローカル開発後の配置先、運用費、LiveKitのホスト方式。
- デザイン、アバター、マップ素材と利用ライセンス。

これらは未決定であり、すべてを最初の実装の前提条件にはしません。ローカルの小さな検証を進め、必要な時点で決定します。

## 音声設計で確認すること

音量をクライアントでゼロにするだけでは、音声データの配信制限にはなりません。会議室や私的な会話の隔離を実装する際は、サーバー側の参加・購読権限で制御し、権限のない参加者が音声を受信できないことを確認します。
