# Waiwai

リモートでも、ふらっと近づいて話せる場所。

Gatherのような2D仮想オフィスの主要な体験を、既存OSSを活用して作るプロジェクトです。テキストチャットはSlackとの連携を前提に検討します。

## 現在の状態

ドット絵の2Dオフィスを、複数人のアバターで一緒に歩けます。同じサーバーのURLから、11種類の部屋を行き来できます。

- 昔の見下ろし型RPGをイメージした、オリジナルのマップ・家具・キャラクター
- 矢印キー / WASDで1マスずつ移動。押し続けると連続移動
- 壁・家具との衝突判定と、部屋の入口を通る移動
- 名前と、性別・表現、体型、身長、肌、髪型・髪の色、服装・服の色、アクセサリーの変更
- オフィスに加え、集中室、作戦室、カフェ、図書室、屋上、アトリエ、ゲーム室、休憩室、工房、星空ラウンジ
- 執務エリア4台と集中室8台の計12台のデスク。ロビーはソファと通路の空間
- 家具・小物ごとに複数URLを設定できる共有のお気に入りと、ホワイトボード前でのリンク一覧
- デスク・椅子と8種類の小物の配置・移動・回転・片づけ、部屋ごとの共有とサーバー保存
- 小さい画面・タッチ端末向けの方向ボタン
- サーバー経由の移動・名前・服の色の同期、参加者と現在地の一覧
- 入退室の反映、切断時の状態表示と自動再接続
- 同じ部屋の近くにいる人との音声通話、距離による音量調整、マイクON / OFF
- 相手のアバター・名前・参加者一覧からSlackアプリのDMを開く導線
- Slackログインによる名前・ワークスペースID・メンバーIDの自動設定
- 全室を対象に名前・SlackメンバーIDで人を検索し、オンライン／オフラインと滞在中の部屋を確認。オンラインの人の隣へワープ

現在は、ゲスト参加もできる共有オフィスのプロトタイプです。Slackアプリを設定するとSlackログインが使え、名前とSlack IDを自動設定します。ゲストは従来の手動設定も使えます。見た目はブラウザー、小物はサーバーに保存します。位置・自席の永続化は未実装です。近接音声は小グループ向けのWebRTC実装です。

- サービス名・リポジトリ名：Waiwai / `waiwai`
- 引き継いだ希望、技術候補、最初の検証範囲：[開発計画](docs/project-plan.md)
- 元の会話：[Gatherとは何か](https://chatgpt.com/share/6ad317da-0558-83ee-8118-d0a30c321a2b)

## 最初に検証したい体験

2人が同じオフィスを歩き、近づくと声が聞こえ、離れると聞こえなくなる。相手のアバターからSlackのDMを開ける。

マップ・移動同期・近接音声・Slack DMへの導線を実装しました。

## ローカル起動

Node.js 22.18以降が必要です（開発時はNode.js 24で確認）。

```bash
npm ci
npm run dev
```

ターミナルに表示されるURL（通常は `http://127.0.0.1:5173/`）をブラウザーで開いてください。APIキーや環境変数は不要です。画面のフォントはGoogle Fontsから読み込み、接続できない場合は代替フォントで表示します。

`npm run dev` は、画面の配信と `/office` のWebSocketサーバーを同じポートで起動します。静的ファイルだけの配信では同期できません。

### 複数人で試す

同じPCでは、同じURLを2つのタブや別ブラウザーで開いてください。タブごとに1人として入室し、名前と服の色を変えると見分けやすくなります。

同じLANの別端末で試す場合は、ホスト側で次のように起動します。

```bash
npm run dev -- --host 0.0.0.0 --port 5173 --strictPort
```

全員で `http://<ホストPCのLAN内IPアドレス>:5173/` を開きます。別端末では `127.0.0.1` の代わりにホストPCのIPアドレスを使います。OSのファイアウォールで接続の許可が必要な場合があります。これは信頼できるLANでの検証向けです。ゲスト参加を許可しているため、接続できる人は全員が同じオフィスに入れます。

上記のHTTP接続では移動同期を試せます。別端末のマイクを使うにはHTTPSで配信してください。音声の使い方とHTTPS・STUN / TURNの設定は[近接音声](docs/proximity-audio.md)を参照してください。

### 近接音声を試す

1. `http://127.0.0.1:5173/` を2つのタブや別ブラウザーで開きます。
2. 両方で「音声に参加」を押します。この時点では聞くだけで、マイクは取得しません。
3. 話す側で「マイクをON」を押し、ブラウザーのマイク使用を許可します。
4. 同じ部屋の5マス未満で声が届きます。1.5マス以内は通常音量、それより遠くは小さくなり、5マス以上または別の部屋では音声接続を閉じます。
5. 「マイクをOFF」で入力を停止、「音声を終了」で送受信を終了します。

実際に話すときはヘッドセットを推奨します。同じPCの複数タブでマイクとスピーカーを使うと音が回り込む場合があります。音声は同時に30人まで、1端末最大4人との接続（5人以内の小グループ）で、録音・文字起こしは行いません。オフィスから切断すると音声も終了し、再接続後はマイクOFFで参加し直します。

### オブジェクトからツールを開く

歩行中にデスク・モニター・会議テーブル・ホワイトボード・配置した家具や小物をクリックすると、そのオブジェクトに登録したリンク一覧が開きます。リンクは明示的に選んで別タブで開きます。リンクのあるホワイトボードの前に立っても同じ一覧を表示します。閉じた後は一度前から離れるまで再表示しません。

「リンクを設定」で共有のお気に入りから複数選び、「この選択を保存」を押します。1オブジェクト10件まで、共有のお気に入りは全室共通で100件までです。リンクの名前とHTTPS URLを入力してお気に入りを追加できます。同じURLは重複登録しません。選択をすべて外して保存すると、そのオブジェクトのリンクだけを解除します。固定家具は入室者が設定でき、配置した家具・小物は配置した本人だけが設定できます。閲覧・リンクを開く操作は全員が使えます。配置・移動・片づけのモード中は家具の編集を優先します。

お気に入りとリンクの割り当ては `WAIWAI_LINKS_FILE`（既定 `.local/office-links.json`）へ保存します。内部URLを含むため、Git管理の対象外です。小物・メンバーのデータと一緒にバックアップし、単一のサーバープロセスだけで書き込んでください。家具を移動・回転してもリンクを引き継ぎ、片づけた家具のリンクは表示しません。リンク先ツールの閲覧権限は各ツールで管理され、Waiwaiへの登録だけでは変わりません。

Azure用デプロイスクリプトは保存先を `/var/lib/waiwai/office-links.json` に設定します。初回のみローカルのお気に入りをSSH経由でコピーし、再デプロイ時はサーバーで保存した設定を保持します。配置家具のデータ移行は別途必要です。

### 見た目・部屋・小物を変える

「見た目を変える」でプレビューを確認して保存します。性別・表現にかかわらず、すべての服・髪型を選べます。見た目はこのブラウザーに保存され、同じ部屋の人にも反映されます。

「部屋を移動」またはマップの矢印ドアから部屋一覧を開きます。一覧には各部屋の人数を表示します。移動先のアバターだけを描画し、元の部屋との音声接続を終了します。「入口にもどる」は現在の部屋の入口へ戻ります。

マップ下の家具・小物欄で種類を選び、「置く」を押して空きマスをクリックします。デスクは3×2マス、椅子は1マスです。デスクは回転すると2×3マスになり、クリックしたマスが配置範囲の左上です。枠のプレビューで空きを確認できます。

「動かす」は自分が置いた家具・小物→移動先の順でクリック、「片づける」は自分の家具・小物をクリックします。大きなデスクは占有範囲のどのマスからも選べます。「回転」で90度ずつ変更、「おわる」またはEscで歩行に戻ります。各部屋合計60個までで、家具の範囲全体について、重なり・アバター・入口・ドア・通り道をふさぐ配置を拒否します。部屋にもともとある固定家具はこの操作の対象外です。

配置は即座に同室の全員へ共有し、`WAIWAI_DATA_FILE`（既定 `.local/office-objects.json`）へ保存します。サーバー再起動後も残ります。このファイルをバックアップし、複数のサーバープロセスから同時に書き込まないでください。Slackログインした本人は次回も自分の小物を編集できます。ゲストの所有権は接続中だけ有効なので、残したい小物はSlackログイン後に配置してください。ブラウザーを閉じたゲストの小物の片づけは、現段階では管理者によるデータファイルの保守が必要です。

### Slackでログインする

[Slackアプリの設定手順](docs/slack-login.md)に従い、`.env.example` を `.env` にコピーして `SLACK_CLIENT_ID`、`SLACK_CLIENT_SECRET`、`SLACK_REDIRECT_URI` を設定し、サーバーを再起動します。開発・本番サーバーとも `.env` を読み込みます。秘密情報に `VITE_` は付けず、Gitにも含めません。

登録したHTTPSのURLでWaiwaiを開き、「Sign in with Slack」を押して対象ワークスペースを選びます。戻ると名前とSlack IDが自動設定され、そのままDM機能を使えます。名前は既存の表示上限に合わせて12文字までです。ログイン中は名前・IDを手動変更せず、服の色は変えられます。

セッションは8時間有効で、再読み込み・同じブラウザーの別タブでも復元します。「ログアウト」は同じセッションの全タブに反映され、ゲストに戻ります。サーバー再起動ではログイン状態が失われます。Slack自体からのログアウトは行いません。

未設定時はログインボタンを表示せず、ゲストとして利用できます。Slackログインには登録済みのHTTPS URLが必要で、HTTPのLAN URLでは利用できません。

### 人を検索して会いに行く

「人を探す」で名前またはSlackメンバーIDを入力し、「すべて／オンライン／オフライン」で絞り込めます。オンラインはWaiwaiへ接続中という意味で、Slack自体の在席状態ではありません。オンラインの人には滞在中の部屋を表示し、「隣へワープ」で同じ部屋の隣接する空きマスへ移動します。壁・家具・他の人・ドアを避け、元の部屋との音声接続も更新します。隣に空きがないときや相手が退出済みのときは移動しません。

検索対象は、Slackログインして一度Waiwaiへ入室したメンバーと、現在接続中のゲストです。未利用のSlackワークスペース全員を取得する機能ではありません。確認済みのSlackアカウントは複数タブを1人にまとめ、最後に接続したタブの部屋を表示します。1つでも接続が残っていればオンラインです。ゲストは退出後に一覧から消えます。通信断は最大約30秒を目安にオフラインへ反映します。

Slackメンバーの名前とIDを `WAIWAI_MEMBERS_FILE`（既定 `.local/office-members.json`）へ保存し、サーバー再起動後もオフラインで検索できます。位置・オンライン状態・認証トークンはこのファイルへ保存しません。保存上限は5,000人で、ファイルは小物と同様にバックアップ対象にしてください。既存メンバーの記録はこの機能を反映した後の入室から始まります。

### Slack DMを開く

1. Slackでログインすると、自分のワークスペースID・メンバーIDが自動設定されます。ゲストの場合は「あなたのSlack」にID（`T…` と `U…` / `W…`）を入力し、「Slack設定を保存」を押します。
2. 相手のアバターか名前、または参加者一覧の名前をクリックすると、その人のSlack DMを開きます。参加者一覧はTab / Enterでも操作できます。
3. Slackアプリをインストールし、対象ワークスペースにログインしておいてください。ブラウザーやOSがアプリを開く確認を表示する場合があります。

未設定の相手を選ぶと設定案内を表示します。ゲストの手動設定は「解除」で共有を停止し、同じタブの再読み込みで復元します。ログイン中のIDはサーバーのセッションから取得します。IDの取得方法と検証範囲は[Slack DM](docs/slack-dm.md)を参照してください。

### 本番用ビルドをローカルで試す

```bash
npm run build
npm start
```

`npm start` と `npm run preview` は、`dist/` の配信と同期サーバーをまとめて起動します。既定は `127.0.0.1:5173` です。`PORT` と `HOST` 環境変数で変更できます。たとえば別ポートなら `PORT=5174 npm start` です。

### 操作

1. マップをクリックするか、Tabキーでマップにフォーカスします。
2. 矢印キーまたはWASDで歩きます。タッチ端末では方向ボタンを使えます。
3. 「入口にもどる」で最初の場所に戻れます。

名前の入力中は移動しません。Tabキーでマップの操作を抜けられます。ウィンドウの切り替えやフォーカス解除時には、押下状態をリセットします。

### 検証とビルド

```bash
npm test          # 移動・音声・Slackリンク・認証・WebSocketのテスト
npm run check     # TypeScriptの型チェック
npm run build     # 型チェックと本番用ビルド（dist/）
npm run preview   # 本番用ビルドをローカルで確認
```

手動確認：2画面で入室し、お互いの移動・名前・服の変更とリセットが反映されること、片方を閉じると退出することを確認します。同期サーバーを一度停止すると操作が止まって再接続を表示し、起動し直すと再入室します。開発サーバーはHMRによるページ再読み込みが入るため、接続復帰そのものの確認には本番用ビルドを使います。

### 同期の仕様

- 移動先と速度はサーバーで検証し、許可された結果を全員に配信します。描画では移動を滑らかに補間します。
- 名前・服の色・設定済みのSlack IDは全員に共有されます。再接続時にも、現在の画面で設定した値を再送します。
- 入室時は入口の近くの空いているマスに配置します。アバター同士の通過は許可します。
- 切断中は移動を止めて自動再接続します。再接続すると新しい参加者IDで入口付近へ戻ります。ページ再読み込み・サーバー再起動後の位置の永続化はありません。
- 正常な退出はすぐ反映します。通信が途絶えた参加者は15秒間隔の応答確認で、最大約30秒を目安に除去します。
- 1サーバープロセスで11部屋を管理し、全室合計の接続上限は150です。Mac上で150人の連続移動と30人の音声シグナリングを試験しました。Azure実機での長時間試験は公開前に必要です。複数サーバー間の同期、固定の自席、プライベートルームは未実装です。

## 実装構成

Vite + TypeScript + Phaser 3に、Node.js + `ws` の同期サーバーを加えています。現在のマス単位の移動を小さなプロトコルで同期するため、まずはWebSocketを採用しました。Colyseusは前の会話で挙がった候補で、現時点では導入していません。

| ファイル | 役割 |
| --- | --- |
| `src/main.ts` / `src/style.css` | 画面、アバター設定、操作ガイド、レスポンシブ表示 |
| `src/game/world.ts` | マップ寸法、家具の配置、通行判定、マス単位の移動モデル |
| `src/game/art.ts` | 図形から生成するドット絵のマップとアバター |
| `src/game/rooms.ts` / `src/game/objects.ts` | 部屋の構成、小物と通行・配置の検証 |
| `src/game/avatar.ts` / `src/game/avatar-editor.ts` | 容姿のデータ、ドット絵、プレビューと保存 |
| `server/objects.ts` | 小物の変更を直列化し、ファイルへ原子的に保存 |
| `src/game/controls.ts` | フォーカスに応じたキー入力と方向ボタン |
| `src/game/OfficeScene.ts` | Phaserによる描画と移動モデルの接続 |
| `src/network/` | 通信メッセージ、接続、再接続と移動要求の管理 |
| `server/office.ts` | 参加者管理、サーバー側の通行・速度判定、認証プロフィールの適用、状態の配信 |
| `server/auth.ts` | Slack OIDC、署名・state・nonce・PKCEの検証、Cookieセッション、ログアウト |
| `vite.config.ts` | 開発用HTTPサーバーへの同期機能の組み込み |
| `server/index.ts` | 本番用ビルドとWebSocketの配信 |
| `src/audio/` | WebRTC接続、マイク、距離による音量と話者表示 |
| `src/slack/` | Slack IDの検証、DMリンク生成、タブ内設定の読み込み |
| `server/voice.ts` | 音声参加・近接ペア・シグナリング・ICE設定 |
| `tests/voice.html` | 開発時だけ使う、マイク不要の合成音による通信検証 |

ゲーム内の画像はコードから生成しており、既存ゲームの画像素材は使用していません。

## 開発の進め方

1. 小さな2Dマップとアバター移動を作る。**実装済み**
2. 複数ブラウザーで位置を同期する。**実装済み**
3. 近接音声を接続し、会話の入りやすさを確かめる。**実装済み**
4. Slackへの導線を加える。**Slackログイン・ID自動設定・DMリンクを実装済み**
