# Waiwai

リモートでも、ふらっと近づいて話せる場所。

Gatherのような2D仮想オフィスの主要な体験を、既存OSSを活用して作るプロジェクトです。テキストチャットはSlackとの連携を前提に検討します。

## 現在の状態

ドット絵の2Dオフィスを、複数人のアバターで一緒に歩けます。同じサーバーのURLから、13種類の部屋を行き来できます。

- 昔の見下ろし型RPGをイメージした、オリジナルのマップ・家具・キャラクター
- 矢印キー / WASDで1マスずつ移動。押し続けると連続移動
- 壁・家具との衝突判定と、部屋の入口を通る移動
- お辞儀・ジャンプ・バンザイ・よろこぶリアクションと、同じ部屋への同期
- 名前と、性別・表現、体型、身長、肌、髪型・髪の色、服装・服の色、アクセサリーの変更
- オフィスに加え、集中室、作戦室、カフェ、図書室、屋上、アトリエ、ゲーム室、休憩室、工房、星空ラウンジ
- 執務エリア4台と集中室8台の計12台のデスク。ロビーはソファと通路の空間
- 家具・小物ごとに複数URLを設定できる共有のお気に入りと、ホワイトボード前でのリンク一覧
- デスク・椅子・監視モニター・サーバーラックと8種類の小物の配置・移動・回転・片づけ、部屋ごとの共有とサーバー保存
- 小さい画面・タッチ端末向けの方向ボタン
- サーバー経由の移動・名前・服の色の同期、参加者と現在地の一覧
- 入退室の反映、切断時の状態表示と自動再接続
- 同じ部屋の近くにいる人との音声通話、距離による音量調整、マイクON / OFF
- 相手のアバター・名前・参加者一覧からSlackアプリのDMを開く導線
- Slackログインによる名前・ワークスペースID・メンバーIDの自動設定
- 全室を対象に名前・SlackメンバーIDで人を検索し、オンライン／オフラインと滞在中の部屋を確認。オンラインの人の隣へワープ

現在は、ゲスト参加もできる共有オフィスのプロトタイプです。Slackアプリを設定するとSlackログインが使え、名前とSlack IDを自動設定します。ゲストは従来の手動設定も使えます。見た目はブラウザー、小物はサーバーに保存します。位置・自席の永続化は未実装です。近接音声は小グループ向けのWebRTC実装です。

- サービス名・リポジトリ名：Waiwai / `waiwai`
- 引き継いだ希望、技術候補、最初の検証範囲：[開発計画](docs/project-plan.md)
- 元の会話：[Gatherとは何か](https://chatgpt.com/share/6ad317da-0558-83ee-8118-d0a30c321a2b)

## 最初に検証したい体験

2人が同じオフィスを歩き、近づくと声が聞こえ、離れると聞こえなくなる。相手のアバターからSlackのDMを開ける。

マップ・移動同期・近接音声・Slack DMへの導線を実装しました。

## ローカル起動

Node.js 22.18以降が必要です（開発時はNode.js 24で確認）。

```bash
npm ci
npm run dev
```

ターミナルに表示されるURL（通常は `http://127.0.0.1:5173/`）をブラウザーで開いてください。APIキーや環境変数は不要です。画面のフォントはGoogle Fontsから読み込み、接続できない場合は代替フォントで表示します。

`npm run dev` は、画面の配信と `/office` のWebSocketサーバーを同じポートで起動します。静的ファイルだけの配信では同期できません。

### 複数人で試す

同じPCでは、同じURLを2つのタブや別ブラウザーで開いてください。タブごとに1人として入室し、名前と服の色を変えると見分けやすくなります。

同じLANの別端末で試す場合は、ホスト側で次のように起動します。

```bash
npm run dev -- --host 0.0.0.0 --port 5173 --strictPort
```

全員で `http://<ホストPCのLAN内IPアドレス>:5173/` を開きます。別端末では `127.0.0.1` の代わりにホストPCのIPアドレスを使います。OSのファイアウォールで接続の許可が必要な場合があります。これは信頼できるLANでの検証向けです。ゲスト参加を許可しているため、接続できる人は全員が同じオフィスに入れます。

上記のHTTP接続では移動同期を試せます。別端末のマイクを使うにはHTTPSで配信してください。音声の使い方とHTTPS・STUN / TURNの設定は[近接音声](docs/proximity-audio.md)を参照してください。

### 近接音声を試す

1. `http://127.0.0.1:5173/` を2つのタブや別ブラウザーで開きます。
2. 両方で「音声に参加」を押します。この時点では聞くだけで、マイクは取得しません。
3. 話す側で「マイクをON」を押し、ブラウザーのマイク使用を許可します。
4. 同じ部屋の5マス未満で声が届きます。1.5マス以内は通常音量、それより遠くは小さくなり、5マス以上または別の部屋では音声接続を閉じます。
5. 「マイクをOFF」で入力を停止、「音声を終了」で送受信を終了します。

実際に話すときはヘッドセットを推奨します。同じPCの複数タブでマイクとスピーカーを使うと音が回り込む場合があります。音声は同時に30人まで、1端末最大4人との接続（5人以内の小グループ）で、録音・文字起こしは行いません。オフィスから切断すると音声も終了し、再接続後はマイクOFFで参加し直します。

### 置き場で乗りものを借りる

ひだまりオフィスのロビー左下に、自転車・スケボー・ローラースケートの置き場があります。置き場の床に踏み入れると、その種類の乗りものを自動で借ります。乗って置き場へ戻ると、自動で返却します。置き場の中を歩き続けても乗り降りは繰り返しません。一度床から出ると次の操作ができます。満車なら徒歩のままなので、戻ってきた後に入り直してください。近くでEキー／マップ下の「乗りもの」から空き台数の確認や手動操作もできます。各3台（スケートは3組）を全員で共有し、1人1つまで。同時に操作しても同じ1台を重複して貸し出しません。空き台数と乗っている姿は全員に同期します。

自転車は歩行の約2倍、スケボーは約1.5倍、スケートは約1.4倍の速さです。壁・家具の判定は徒歩と同じです。乗ったまま部屋移動や人の横へのワープができ、バディも追従します。返すときはどの種類の置き場でも利用できます。近くでは「置き場に返す」ボタンも使えます。切断・退出時は自動返却し、再接続時は徒歩に戻ります。貸し出しはその場の状態として管理し、サーバー再起動時にも全台返却します。

### ゲームセンターで一緒に遊ぶ

「部屋を移動」→「ワイワイゲームセンター」へ。8台の筐体・その下のラベル、または上部の「ゲームを選ぶ / 観戦する」から開きます。ゲームを選び「参加する」→「スタート」。**全8種類、一人でも遊べます。** 友だちを待ってから開始してもOK。参加せずに観戦もできます。

| ゲーム | 人数・時間 | あそび方 |
| --- | --- | --- |
| ほしの四目ならべ | 一人CPU対戦 / 二人、最大90秒 | 7列×6段に交互に星を落とし、縦・横・斜めに4つつなぐ。時間切れ・満杯は引き分け。CPUは勝てる列や相手の連続した星を見て打ちます。 |
| せーので、ピカッ！ | 一人CPU対戦 / 二人、30〜60秒 | ランダムに点灯したら押す5本勝負。フライングは相手に1点。無入力でも進行。 |
| みんなで流星ガード | 一人 / 2〜4人協力、60秒 | 3レーンの隕石を迎撃して街のHPを守る。数字の1・2・3でも操作、0.45秒に1発。一人のときは隕石の間隔を長くします。 |
| オフィス手拍子 | 1〜4人、約32秒 | 光の輪が重なる拍に、ボタンかスペースで手拍子。 |
| ねこのまねっこ | 1〜4人、約32秒 | ねこの左右3拍のお手本を覚え、少し後の拍でまねする。左1・右2。 |
| ロボット仕分け | 1〜4人、約35秒 | ベルトの箱が中央に来たら、その矢印へ。左1・右2。 |
| 流れ星キャッチ | 1〜4人、約36秒 | 3レーンを横切る星を中央線でキャッチ。上から1・2・3。 |
| カフェのトースト | 1〜4人、約34秒 | 合図で一度押して焼き、目盛りで再度押して取り出す。焼き時間はパンごとに違います。スペースでも操作。 |

追加の5種類は、同じお題を同時に遊んで個別の得点と最高コンボを比べられます。ぴったりなら30点、少しずれても15点。判定幅は前後340msで、連打や判定済みの拍の再送では得点を増やせません。任意の「効果音 ON」で短い電子音が拍とお手本を伝えます。音なしでも合図・図・文字で遊べます。閉じた画面や非表示タブでは効果音を止めます。

1人が参加できるのは1台、各台で同時に1試合です。開始後の途中参加は観戦となり、次の試合から参加できます。画面を閉じても参加は続き、「退席する」・別室移動・ワープ・切断で抜けます。四目ならべ・早押しの対戦中の退席は終了、協力・リズム遊びは残ったメンバーで続行。待機席は最後の参加から2分、終了後は1分で解放し、全員が抜けた台も初期化します。CPUだけで席を占有し続けることはありません。「もう一回！」で再戦できます。

手番・勝敗・タイマー・乱数・迎撃・得点・参加上限はサーバーが判定。途中入室で全台の状態を取得し、その後は変化した台の状態だけをゲームセンター内へ配信します。描画と電子音の生成は各端末で行い、ゲーム用の追加サービス・データベース・画像や音声ファイルのダウンロードは不要です。状態はメモリ上にあり、再接続・サーバー再起動後は再参加が必要です。早押し・リズムの判定はサーバー到着時刻が基準となるカジュアル向けで、競技向けの通信遅延補正は行いません。

### 巨大ロボットの操縦室で遊ぶ

「部屋を移動」→「ワイワイガー操縦室」で13番目の部屋へ入れます。オフィス全体が巨大ロボット `WAIWAI-01`（ワイワイガー）の内部という設定です。部屋一覧と現在の部屋に部位を表示し、操縦画面の全身図では頭部・胴体・左右の腕と脚を選んで、そこにある部屋へ移動できます。既存の部屋の名前・用途は保ちます。

正面スクリーン、全身ホログラム、左右の操縦パネル、レーダー、パイロット席と見学席を配置しています。パイロット席の手前（15,13）で止まると上向きに座ります。パネル・全身図・レーダー・席のクリック、または上部の「操縦する」からシミュレーターを開きます。起動・手振り・歩行テスト・ロケットパンチ・バリア・決めポーズの6種類を遊べます。コマンド中は機体と正面スクリーンが動き、操縦した人の名前を表示します。

操縦室にいる人全員に同じ開始時刻・コマンドを共有し、途中入室でも進行中の演出を受け取ります。1回6.5〜8秒で待機に戻り、その間はほかのコマンドを受け付けません。操縦室以外からの操作はサーバーが拒否し、演出の配信先も操縦室だけです。サーバー再起動時は待機に戻ります。演出の間も歩いたり会話したりでき、別の部屋の状態は変えません。端末の動きを減らす設定では静止したポーズで表します。音は鳴らしません。

この部屋の正面映像は訓練用のカメラ映像で、街の窓とは別の室内スクリーンです。照明は窓のない室内として扱います。壁掛けカレンダーは共通で使えます。日替わり事件は以前の12部屋を抽選対象に保ち、過去の発生場所を変えません。

### 毎日の事件・図鑑と館内カレンダー

全13部屋の北側の壁にカレンダーがあります。クリックすると月表示が開き、日付ごとに館内で共有した会議・定例と事件の記録を確認できます。マップ上部の「館内カレンダー」からも開けます。予定は「予定を追加・編集」から既存の共有予定に登録します。単発・毎日・平日・毎週を展開し、停止中の予定は月表示から除外します。時刻はすべてJSTです。

事件は26テーマ・365本の個別エピソードです。隕石、泥棒、洪水、サンタ、ゴーストバスターズ、ウォーリー、デロリアン、ターミネーター、昔話、漫画の来客、窓の外のゴジラなどを用意しています。テーマごとのピクセルアートと各話の小物・解説を使い、洪水では床に水面、屋外の来客では窓や屋上のパノラマに演出を加えます。ゲームの移動・家具・音声の状態は変えません。

毎日JSTの0:00に館内のどこか1部屋で1件が発生します。2026年10月17日を起点とした365日単位のシャッフルで、一巡するまで同じエピソードは重複しません。初日はシャーロックの訪問です。以降の順番と部屋も日付から決まり、再起動・途中入室でも変わりません。サーバーが初回入室と日付変更時に全員へ同じ状態を送ります。日付変更の確認は1秒間隔です。窓の外の事件は窓のない管制室には発生しません。

上部の「現場を見に行く」で該当の部屋へ移動できます。来客・小物のクリック、またはその部屋の「事件を調べる」で解説が開き、発見済みの印をこのブラウザーのlocalStorageに保存します。「事件の図鑑」とカレンダーから、今日を含む直近365日を振り返れます。記録は機能の開始日からで、未来の事件は表示しません。印はSlackアカウント間・別ブラウザー間では同期しません。保存できない環境では、その画面を開いている間のみ印を保持します。

出来事の選択・履歴は日付とバージョン固定のカタログから復元するため、新しい永続ファイルやDBは不要です。履歴を維持するには `daily-events.ts` の起点・抽選シードと `daily-event-catalog.ts` の既存ID・並び順を変更しないでください。予定の月表示は現在登録されているルールから計算するため、変更・削除前の予定を残す監査ログではありません。

開発中は `/dev/events-preview.html` で全365エピソード・部屋別の演出を確認できます。このページで選んだ内容は実際の館内に影響せず、本番ビルドにも含みません。

### 館内放送と会議・定例の予定

マップ上部の「館内放送を出す」でタイトルと本文を入力すると、全フロアの人に同じテキストが表示されます。だれでも放送・終了できます。表示時間は1・3・5・10分で、途中で入室した人にも表示します。手動放送は同時5件まで、送信間隔は10秒です。音声やSlackメッセージは送信しません。

「予定・定例を設定」は別の画面です。開始日時をJSTで指定し、単発・毎日・平日（月〜金）・毎週から選べます。毎週の曜日は最初の開始日で決まります。開始時または5・10・15分前から告知し、開始後1・3・5・10分まで表示します。予定は全員で共有して50件まで登録でき、だれでも編集・停止・再開・削除できます。同時編集で古い内容が上書きされる場合は保存を止め、開き直すよう案内します。

予定と放送はサーバーで保存し、ブラウザーを閉じてもサーバーが動いていれば自動で告知します。サーバーの確認間隔は5秒です。再起動後も表示時間内なら再開し、同じ予定を重複して放送しません。停止中に表示時間まで過ぎた予定は後から流しません。登録した予定は館内カレンダーでも確認できます。外部カレンダーとの同期は行いません。

保存先は `WAIWAI_ANNOUNCEMENTS_FILE`。未指定なら家具データと同じディレクトリの `office-announcements.json`（既定 `.local/office-announcements.json`）です。社内の会議情報を含むためGit管理せず、家具・リンクと一緒にバックアップしてください。単一のサーバープロセスで管理します。Azureでは家具と同じ永続ディレクトリに保存し、再デプロイでも保持します。

### 椅子や机に座る・自販機でひと息

ソファ、固定のデスク・作業台・テーブルの椅子、配置したデスク・オフィスチェアの正面のマスで止まると、自動で座ります。移動すると立ち上がり、乗りものの利用中は座りません。リアクション中は一時的に立ち、終わると座り直します。長いソファは横に並んで座れます。回転した家具の向きに合わせて着席し、家具を移動・片づけすると座る場所も追従します。参加者一覧に「着席中」と表示し、同じ部屋の人にも座って見えます。家具そのもののマスは引き続き通れません。

カフェ右上と休憩室右側の壁際に自販機があります。すぐ隣（上下左右1マス）まで行くと、自動でペットボトルを持ちます。服・髪型・体型は変えず、持ちものだけを置き換えます。同じ自販機の前では繰り返し受け取らず、一度離れると再び受け取れます。持ちものはほかの参加者にも同期し、ブラウザーに保存します。「見た目を変える」から外したり変更したりできます。

### ちょっと不思議な落とし物

落とし物は**全館合計で最大3種類・各1個**。13部屋のうち、選ばれた3つの部屋に1個ずつ現れます。同じ種類を別の部屋に複製しません。元の10種類に、一つずつ名前と解説を書いた365種類を追加し、計375種類になりました。40系統のピクセル絵と小さな色違いの札を使っています。

30分ごとに、375種類のシャッフルした山札から3種類を引きます。一巡するまで同じ種類は再登場せず、125回の入れ替えで全375種類が登場します。サーバーが館内共通の種類・部屋・位置・有効期限を配信するため、端末の時計や部屋移動では別の落とし物を生成しません。途中参加も同じ状態を取得し、切断中の画面では落とし物を消します。

犬・猫と同じように、クリックすると名前と短い解説が開き、マップ下の「床の落とし物」からも選べます。通り道をふさがない装飾で、入口・乗りもの置き場・着席位置・家具の上を避けます。家具を重ねると同じ部屋の空き場所へ移動し、無関係な家具の追加では移動しません。置き場所がない部屋の分は非表示にして、ほかの部屋に増殖させません。拾って所持する機能はありません。

開発サーバーの `/dev/lost-items-preview.html` で、全375種類の名前・解説・絵を検索して確認できます。この一覧は本番ビルドには含めません。

### リアクションで気持ちを伝える

マップ下の「気持ちを伝える」から、お辞儀・ジャンプ・バンザイ・よろこぶを選べます。マップにフォーカスがあるときは1〜4キーでも操作できます。名前やURLなどの入力欄ではショートカットは反応しません。同じ部屋の参加者へ動作を共有し、短時間で立ち姿へ戻ります。歩行・位置リセット・部屋移動・退出でも動作を終了します。

ジャンプは足元の影を床に残したままアバターを上げ、バンザイは両手を上げます。服装や容姿を保ってポーズを変え、動作中は短い言葉も添えます。端末の「視差効果を減らす／アニメーションを減らす」（`prefers-reduced-motion`）設定では跳躍・揺れ・伸縮を控え、ポーズと言葉で伝えます。

連打による表示の混雑を防ぐため、次の動作まで約2秒待ちます。リアクションはその場の短いイベントで、保存や後から入った人への再生は行いません。

### 図書室に手順書・マニュアルを置く

「部屋を移動」から「星灯り図書室」へ。手順書・マニュアル・Confluence・設計資料・議事録・ナレッジの6つの棚があり、クリックすると棚ごとの資料一覧を開きます。「リンクを設定」→「資料を追加」で資料名とConfluenceなどのHTTPS URLを登録し、並べたい資料にチェックして「この選択を保存」を押します。登録済みのお気に入りからも選べます。棚ごとに最大10件を保存し、参加者全員が資料名を選んで別タブで開けます。実際の社内URLは画面から設定してください。

「家具・小物」の「資料の本棚」（4×1マス）を選ぶと、図書室やほかの部屋にも本棚を置けます。配置後に歩行モードで棚をクリックして資料を設定します。ほかの家具と同じように移動・回転・片づけができ、移動しても登録した資料を保持します。配置した棚の設定は配置者が変更でき、固定の棚は入室者が設定できます。資料の登録内容は共有・保存されます。リンク先へのアクセス権限はConfluenceなどのサービス側で管理します。

### システム管制室を使う

「部屋を移動」から「システム管制室」へ入れます。CloudWatch・New Relic・サービス稼働状況・ログ検索・アラート・デプロイのモニター、インフラ用のラック、障害対応テーブル、手順書の本棚を用意しています。それぞれのオブジェクトから登録済みのダッシュボードなどを別タブで開けます。「リンクを設定」で複数のURLを変更できます。

モニターのグラフィックは部屋の装飾です。実際のメトリクスや障害情報は、登録した監視ツール側で確認します。URLとツールの認証情報は別で管理され、各利用者が閲覧権限のあるアカウントでツールにログインします。まだURLのない端末には「リンクを設定」から追加してください。監視モニター（3×2マス）とサーバーラック（2×2マス）は、家具・小物メニューから追加配置・移動・回転・片づけもできます。

### オブジェクトからツールを開く

歩行中にデスク・モニター・会議テーブル・ホワイトボード・配置した家具や小物をクリックすると、そのオブジェクトに登録したリンク一覧が開きます。リンクは明示的に選んで別タブで開きます。リンクのあるホワイトボードの前に立っても同じ一覧を表示します。閉じた後は一度前から離れるまで再表示しません。

「リンクを設定」で共有のお気に入りから複数選び、「この選択を保存」を押します。1オブジェクト10件まで、共有のお気に入りは全室共通で100件までです。リンクの名前とHTTPS URLを入力してお気に入りを追加できます。同じURLは重複登録しません。選択をすべて外して保存すると、そのオブジェクトのリンクだけを解除します。固定家具は入室者が設定でき、配置した家具・小物は配置した本人だけが設定できます。閲覧・リンクを開く操作は全員が使えます。配置・移動・片づけのモード中は家具の編集を優先します。

お気に入りとリンクの割り当ては `WAIWAI_LINKS_FILE`（既定 `.local/office-links.json`）へ保存します。内部URLを含むため、Git管理の対象外です。小物・メンバーのデータと一緒にバックアップし、単一のサーバープロセスだけで書き込んでください。家具を移動・回転してもリンクを引き継ぎ、片づけた家具のリンクは表示しません。リンク先ツールの閲覧権限は各ツールで管理され、Waiwaiへの登録だけでは変わりません。

Azure用デプロイスクリプトは保存先を `/var/lib/waiwai/office-links.json` に設定します。初回のみローカルのお気に入りをSSH経由でコピーし、再デプロイ時はサーバーで保存した設定を保持します。配置家具のデータ移行は別途必要です。

### 時刻に合わせた照明・窓の風景

全13部屋の照明がJSTで自動的に変わります。朝6〜10時は朝日、昼10〜16時は自然光、夕方16〜19時は夕日、夜19〜翌6時は電灯・窓の夜景になります。境目の20分前から色と明るさを少しずつ変えます。マップ下に現在の日本時間と照明を表示します。ページを開いたままでも毎分更新し、部屋移動にも反映します。

屋上はランタン、屋内は壁の電灯を点けます。配置したフロアランプの移動・回転・片づけにも光が追従し、管制室やゲーム室ではモニターの光も加わります。アバターの名前は暗くせず、夜も操作に必要な明るさを残しています。端末の時計を基準とし、端末のタイムゾーンにかかわらずUTC+9を使います。季節や地域による日の出・日の入り時刻は扱いません。

窓のある屋内の部屋では、マップ上部の大きな窓にお台場・レインボーブリッジ・東京タワーをイメージした東京湾の街並みと、朝日・昼の太陽・夕日・月と夜景が見えます。実際の位置関係を再現した景観ではありません。 システム管制室には窓を設けず、外の天気の影響を受けない電灯とモニターで照らします。屋上は窓枠のない屋外の背景にし、高い位置から東京湾を見下ろすように、遠くの街並みと広い海、手前のビルの屋根や設備を描きます。朝は淡い青空と薄い金色、夕方はピンクとオレンジ。夜は橋とタワーのライトアップや水面の反射も描きます。晴れ・雨・雷雨は30分ごとの共通の抽選で変化します。同じ時刻なら参加者全員に同じ天気が表示され、再読み込みや部屋移動で抽選し直しません。実際の気象情報ではなくオフィス内の演出です。雨・雷雨では日差しを弱め、昼でも電灯を少し点けます。雨粒と雷の弱い光は窓の中だけに表示し、雷の音は鳴らしません。「動きを減らす」設定では雨粒を静止し、雷も静止した小さなマークで示します。

開発用Viteサーバーの `/dev/lighting-preview.html` では、同じ部屋の朝・昼・夕方・夜を並べ、晴れ・雨・雷雨や動きを抑える設定を確認できます。本番ビルドにはこの確認ページや手動切り替えUIを含めません。

### バディと館内に暮らす仲間

「バディを選ぶ」にピカチュウ・イーブイ・カビゴンとロボット掃除機を追加しました。お気に入りを付けたり、アバターのあとについて歩かせたりできます。ほかの参加者にも同じ種類と動きが見えます。

館内をうろちょろする仲間は、それぞれ1体だけです。犬はひだまりオフィス、猫は星灯り図書室、ロボット掃除機は木漏れ日カフェ、ピカチュウはゲーム室、イーブイは屋上ガーデン、カビゴンは休憩室にいます。それぞれの部屋の中を歩き、ほかの部屋へ移動しても同じ個体を増やしません。仲間のいない部屋もあります。クリックすると名前と説明を開きます。

### アバターの歩き方を選ぶ

「見た目を変える」→「歩き方」で、ふつう・小走り・スキップ・ぴょこぴょこ・のしのし・すいすいの6種類から選び、「この見た目にする」で保存します。設定画面では動くプレビューを見て選べ、停止・再開や向きの変更もできます。歩き方はこのブラウザーに保存し、ほかの参加者や途中から入室した人にも共有します。以前の保存設定・クライアントは、服装や持ちものを保ったまま「ふつう」を使います。

歩き方はアバターと影の描画だけを変えます。どれも同じ速さで移動し、通れる場所や音声の距離は変わりません。止まると通常の姿勢に戻り、着席・乗りもの・リアクション中には歩く演出を重ねません。端末の `prefers-reduced-motion` 設定では上下の跳躍・揺れ・傾き・伸縮と足踏みを停止します。

### アバターに持ちものを設定する

「見た目を変える」→「持ちもの」で、マグカップ・ペットボトル・サンドイッチを選び、「この見た目にする」で保存します。「なし」で外せます。服・体型・アクセサリーと組み合わせられ、歩行やリアクション中も手元に表示し、ほかの参加者にも同期します。選択はこのブラウザーに保存します。以前の見た目設定は、持ちものだけ「なし」として引き継ぎます。

### 見た目・部屋・小物を変える

「見た目を変える」でプレビューを確認して保存します。性別・表現にかかわらず、すべての服・髪型を選べます。見た目はこのブラウザーに保存され、同じ部屋の人にも反映されます。

「部屋を移動」またはマップの矢印ドアから部屋一覧を開きます。一覧には各部屋の人数を表示します。移動先のアバターだけを描画し、元の部屋との音声接続を終了します。「入口にもどる」は現在の部屋の入口へ戻ります。

マップ下の家具・小物欄で種類を選び、「置く」を押して空きマスをクリックします。デスクは3×2マス、椅子は1マスです。デスクは回転すると2×3マスになり、クリックしたマスが配置範囲の左上です。枠のプレビューで空きを確認できます。

「動かす」は自分が置いた家具・小物→移動先の順でクリック、「片づける」は自分の家具・小物をクリックします。大きなデスクは占有範囲のどのマスからも選べます。「回転」で90度ずつ変更、「おわる」またはEscで歩行に戻ります。各部屋合計60個までで、家具の範囲全体について、重なり・アバター・入口・ドア・通り道をふさぐ配置を拒否します。部屋にもともとある固定家具はこの操作の対象外です。

配置は即座に同室の全員へ共有し、`WAIWAI_DATA_FILE`（既定 `.local/office-objects.json`）へ保存します。サーバー再起動後も残ります。このファイルをバックアップし、複数のサーバープロセスから同時に書き込まないでください。Slackログインした本人は次回も自分の小物を編集できます。ゲストの所有権は接続中だけ有効なので、残したい小物はSlackログイン後に配置してください。ブラウザーを閉じたゲストの小物の片づけは、現段階では管理者によるデータファイルの保守が必要です。

### Slackでログインする

[Slackアプリの設定手順](docs/slack-login.md)に従い、`.env.example` を `.env` にコピーして `SLACK_CLIENT_ID`、`SLACK_CLIENT_SECRET`、`SLACK_REDIRECT_URI` を設定し、サーバーを再起動します。開発・本番サーバーとも `.env` を読み込みます。秘密情報に `VITE_` は付けず、Gitにも含めません。

登録したHTTPSのURLでWaiwaiを開き、「Sign in with Slack」を押して対象ワークスペースを選びます。戻ると名前とSlack IDが自動設定され、そのままDM機能を使えます。名前は既存の表示上限に合わせて12文字までです。ログイン中は名前・IDを手動変更せず、服の色は変えられます。

セッションは8時間有効で、再読み込み・同じブラウザーの別タブでも復元します。「ログアウト」は同じセッションの全タブに反映され、ゲストに戻ります。サーバー再起動ではログイン状態が失われます。Slack自体からのログアウトは行いません。

未設定時はログインボタンを表示せず、ゲストとして利用できます。Slackログインには登録済みのHTTPS URLが必要で、HTTPのLAN URLでは利用できません。

### 人を検索して会いに行く

「人を探す」で名前またはSlackメンバーIDを入力し、「すべて／オンライン／オフライン」で絞り込めます。オンラインはWaiwaiへ接続中という意味で、Slack自体の在席状態ではありません。オンラインの人には滞在中の部屋を表示し、「隣へワープ」で同じ部屋の隣接する空きマスへ移動します。壁・家具・他の人・ドアを避け、元の部屋との音声接続も更新します。隣に空きがないときや相手が退出済みのときは移動しません。

検索対象は、Slackログインして一度Waiwaiへ入室したメンバーと、現在接続中のゲストです。未利用のSlackワークスペース全員を取得する機能ではありません。確認済みのSlackアカウントは複数タブを1人にまとめ、最後に接続したタブの部屋を表示します。1つでも接続が残っていればオンラインです。ゲストは退出後に一覧から消えます。通信断は最大約30秒を目安にオフラインへ反映します。

Slackメンバーの名前とIDを `WAIWAI_MEMBERS_FILE`（既定 `.local/office-members.json`）へ保存し、サーバー再起動後もオフラインで検索できます。位置・オンライン状態・認証トークンはこのファイルへ保存しません。保存上限は5,000人で、ファイルは小物と同様にバックアップ対象にしてください。既存メンバーの記録はこの機能を反映した後の入室から始まります。

### Slack DMを開く

1. Slackでログインすると、自分のワークスペースID・メンバーIDが自動設定されます。ゲストの場合は「あなたのSlack」にID（`T…` と `U…` / `W…`）を入力し、「Slack設定を保存」を押します。
2. 相手のアバターか名前、または参加者一覧の名前をクリックすると、その人のSlack DMを開きます。参加者一覧はTab / Enterでも操作できます。
3. Slackアプリをインストールし、対象ワークスペースにログインしておいてください。ブラウザーやOSがアプリを開く確認を表示する場合があります。

未設定の相手を選ぶと設定案内を表示します。ゲストの手動設定は「解除」で共有を停止し、同じタブの再読み込みで復元します。ログイン中のIDはサーバーのセッションから取得します。IDの取得方法と検証範囲は[Slack DM](docs/slack-dm.md)を参照してください。

### 本番用ビルドをローカルで試す

```bash
npm run build
npm start
```

`npm start` と `npm run preview` は、`dist/` の配信と同期サーバーをまとめて起動します。既定は `127.0.0.1:5173` です。`PORT` と `HOST` 環境変数で変更できます。たとえば別ポートなら `PORT=5174 npm start` です。

### 操作

1. マップをクリックするか、Tabキーでマップにフォーカスします。
2. 矢印キーまたはWASDで歩きます。タッチ端末では方向ボタンを使えます。
3. 「入口にもどる」で最初の場所に戻れます。

名前の入力中は移動しません。Tabキーでマップの操作を抜けられます。ウィンドウの切り替えやフォーカス解除時には、押下状態をリセットします。

### 検証とビルド

```bash
npm test          # 移動・音声・Slackリンク・認証・WebSocketのテスト
npm run check     # TypeScriptの型チェック
npm run build     # 型チェックと本番用ビルド（dist/）
npm run preview   # 本番用ビルドをローカルで確認
LOAD_ARCADE=true LOAD_SECONDS=30 npm run test:load  # 150接続・8台28人プレイ・30人の音声シグナリング
```

ゲーム追加時のMacローカル30秒試験：150接続、28人が8台でプレイ、30人が音声シグナリング、移動28,299回、ゲーム操作438回で切断0。ゲーム応答p95は25.2ms、移動応答p95は5.2ms。実音声の転送、インターネット越しの遅延、Azure実機は含みません。

手動確認：2画面で入室し、お互いの移動・名前・服の変更とリセットが反映されること、片方を閉じると退出することを確認します。同期サーバーを一度停止すると操作が止まって再接続を表示し、起動し直すと再入室します。開発サーバーはHMRによるページ再読み込みが入るため、接続復帰そのものの確認には本番用ビルドを使います。

### 同期の仕様

- 移動先と速度はサーバーで検証し、許可された結果を全員に配信します。描画では移動を滑らかに補間します。
- 名前・服の色・設定済みのSlack IDは全員に共有されます。再接続時にも、現在の画面で設定した値を再送します。
- 入室時は入口の近くの空いているマスに配置します。アバター同士の通過は許可します。
- 切断中は移動を止めて自動再接続します。再接続すると新しい参加者IDで入口付近へ戻ります。ページ再読み込み・サーバー再起動後の位置の永続化はありません。
- 正常な退出はすぐ反映します。通信が途絶えた参加者は15秒間隔の応答確認で、最大約30秒を目安に除去します。
- 1サーバープロセスで13部屋を管理し、全室合計の接続上限は150です。Mac上で150人の連続移動と30人の音声シグナリングを試験しました。Azure実機での長時間試験は公開前に必要です。複数サーバー間の同期、固定の自席、プライベートルームは未実装です。

## 実装構成

Vite + TypeScript + Phaser 3に、Node.js + `ws` の同期サーバーを加えています。現在のマス単位の移動を小さなプロトコルで同期するため、まずはWebSocketを採用しました。Colyseusは前の会話で挙がった候補で、現時点では導入していません。

| `src/game/art.ts` | 図形から生成するドット絵のマップとアバター |

## 開発の進め方

1. 小さな2Dマップとアバター移動を作る。**実装済み**
2. 複数ブラウザーで位置を同期する。**実装済み**
3. 近接音声を接続し、会話の入りやすさを確かめる。**実装済み**
4. Slackへの導線を加える。**Slackログイン・ID自動設定・DMリンクを実装済み**

今後の機能追加に合わせて、このREADMEに必要な環境変数、起動手順、検証手順を追加します。

## Azure / Terraform

固定URL、HTTPS、音声中継、Slack入室制限を含む構成と、このMacのツール設定は[Azure公開手順](docs/azure.md)を参照してください。

## Azure IaC（dev）

アプリと同じリポジトリの `infra/` でTerraformを管理します。現在はdevのみで、命名・タグの共通化とリソース種別ごとのファイル分割を行っています。[IaC入口](infra/README.md)、[設計書](docs/infrastructure/azure-design.md)、[命名規則](docs/infrastructure/naming.md)、[構築手順](docs/azure.md)を参照してください。認証不要の検証は `npm run infra:check`。CIは検証のみでAzureへapplyしません。
